Concept & Theory: Broken Access Control

What is Broken Access Control?

Every website has rules about who is allowed to do what. A normal user shouldn't be able to act like an admin. One customer shouldn't be able to see another customer's private data. These rules together are called Access Control.

Broken Access Control (BAC) happens when those rules fail — when the website doesn't properly check permissions before letting someone view a page, change data, or perform an action. The person didn't need to "hack" anything complicated — they simply did something the app should have blocked, and it didn't.

🏢 Analogy

Think of a company building with security guards at every door. Broken Access Control is what happens when a guard forgets to check ID, checks it incorrectly, or isn't posted at a door at all — letting people walk into rooms they were never supposed to enter.

The 7 Variants

1️⃣ Vertical Privilege Escalation

A normal user gains access to admin-level features. This happens when the application fails to properly check the user's role.

Example: Normal user accesses /admin and can delete users.

2️⃣ Horizontal Privilege Escalation (IDOR)

A user accesses another user's data with the same privilege level. Usually happens when the server doesn't verify resource ownership.

Example: Changing id=123 to id=124 shows another user's account.

3️⃣ Horizontal → Vertical Escalation

An attacker first accesses another user's account through a horizontal flaw. That account may belong to an administrator, giving higher privileges.

Example: IDOR exposes an admin account's sensitive functionality.

4️⃣ URL-Based Access Control Bypass

The application blocks a restricted URL but fails to block alternative ways to reach it. Differences in URL formatting or routing may bypass the check.

Example: /admin is blocked, but /admin/ or another route reaches the same function.

5️⃣ Method-Based Bypass

Access control is applied to one HTTP method but not another. The attacker changes the request method to bypass the restriction.

Example: POST /admin/delete is blocked, but GET /admin/delete?id=5 works.

6️⃣ Multi-Step Process Bypass

A sensitive action requires multiple steps, but only some steps have authorization checks. The attacker directly sends the final request and skips the protected steps.

Example: Directly sending the final "confirm role change" request.

7️⃣ Referer-Based Access Control Bypass

The application trusts the Referer header to decide whether a user is authorized. Since the header can be modified by the client, an attacker can forge it.

Example: Sending Referer: /admin to access an admin-only action.
