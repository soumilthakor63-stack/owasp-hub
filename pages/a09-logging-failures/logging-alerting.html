Concept & Theory: Logging & Alerting Failures

What is Logging & Alerting?

Logging = automatic record-keeping of events (who did what, when) — like a security guard's notebook.

Alerting = a system that watches logs in real-time and notifies humans when something suspicious happens — like the guard calling a supervisor.

Logging & Alerting Failure = this system is missing, broken, or ignored, so attacks go unnoticed for a long time (or forever).

Common Causes

  • Nothing gets logged at all.
  • Logs exist but nobody/nothing watches them (no alerts).
  • Logs stored insecurely — attacker deletes/edits them after breaching the system.
  • Sensitive data (passwords, card numbers) accidentally logged in plaintext.
  • Alert fatigue — too many false alerts, so real ones get ignored.

Real-World Example

Equifax 2017: Attackers were inside the network for weeks/months undetected. ~147 million records were stolen because the logging and alerting mechanisms failed to flag the breach.

Testing & Remediation

How a Pentester Tests This

1. Trigger suspicious behavior (e.g., repeated failed logins).

2. Check if the behavior is logged.

3. Check if the log entry triggers an alert.

4. Check log content for leaked sensitive data.

5. Check if logs can be tampered with (deleted/edited).

6. Measure the response time of the security team.

Demo: Vulnerable vs. Secure

Vulnerable System: 5 failed login attempts result in zero records kept and zero alerts fired. An attacker succeeds with no trace left behind.

Secure System: Every attempt is logged with a timestamp. After 3 failed attempts, an automatic alert fires to the security team. A full evidence trail is saved.
